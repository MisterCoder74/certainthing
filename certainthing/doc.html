CertainThing Project Documentation

CertainThing is a PHP + vanilla JavaScript AI coding assistant with a split interface: chat on the left, reasoning/preview on the right. It supports streaming responses, multimodal inputs, website analysis, session persistence, ZIP export, one-key deploy, and GitHub push.

Dark Theme: #0d1117 Accent: #58a6ff SSE Streaming Vanilla JS + PHP

Architecture Summary

  • Frontend: single-page UI rendered in certainthing/index.php and powered by assets/app.js.
  • Backend: REST-style PHP endpoints in certainthing/api/.
  • Streaming: chat endpoint emits SSE events (reasoning, content, status, usage, error).
  • Persistence: JSON storage in certainthing/data/ (users + per-session history).
  • Deploy model: generated files can be exported (ZIP), deployed to local web folder, or committed to GitHub.

Primary Use Cases

1) Build a project from scratch

User describes desired app; AI streams reasoning and complete multi-file code; user previews, iterates, exports/deploys.

2) Analyze and clone a website

User pastes URL; scraper fetches content; AI summarizes structure and generates an inspired/replicated implementation.

3) Generate UI from design image

User uploads JPG/PNG/WebP screenshot; AI infers layout/style and produces matching frontend code.

4) Refactor existing codebase snippets

User uploads source files (HTML/CSS/JS/PHP/etc.); AI edits or extends existing code while keeping context.

5) Ship output quickly

Generated code can be downloaded as ZIP, deployed live by pressing F10, or pushed directly to GitHub.

Use Flows by Feature

F1 — Conversational Chat + Streaming

  1. User submits prompt (optional attachments/URLs).
  2. Frontend posts FormData to api/chat.php.
  3. Backend builds prompt + history, calls OpenAI with streaming enabled.
  4. SSE events stream into UI; assistant bubble is built incrementally.

F2 — Reasoning Trace Pane

  1. chat.php emits reasoning events for loading, scraping, and model reasoning deltas.
  2. appendReasoning() updates current step in real time.
  3. Status badge moves through Thinking → Generating → Done.

F3 — Code Renderer + Multi-file Tabs + ZIP Export

  1. Assistant response is parsed for fenced code blocks.
  2. finalizeAssistantMessage() groups adjacent blocks into tabbed multi-file UI.
  3. Per-file actions: copy, download; grouped actions: ZIP export, GitHub push.

F4/F5 — Image & File Understanding

  1. User selects files in attachment picker.
  2. upload.php converts images to data URLs or reads text content.
  3. Attachment payload is appended to message and included in model context.

F6 — Website Analyzer

  1. URL regex detects links in prompt text.
  2. chat.php calls scrape_url() for each URL.
  3. Sanitized website text is injected into prompt context before model request.

F7/F8 — Iteration + Session Persistence

  1. Each turn is appended to session JSON file {user}_{session}.json.
  2. Sidebar loads sessions via get_sessions.php.
  3. User can switch/search/delete sessions without leaving app.

F9 — Export as ZIP

  1. Frontend posts extracted files to export.php.
  2. Backend creates temp ZIP and streams it as attachment download.

F10 — Deploy (F10 / button)

  1. Frontend extracts last assistant code blocks and deduplicates names.
  2. deploy.php writes files to deploy/{user}/{session}.
  3. UI shows live URL card; user opens deployed app in new tab.

F11 — Email/Password Auth

  1. Register stores bcrypt hash in users.json.
  2. Login validates via password_verify() and sets PHP session.
  3. Protected APIs call check_auth() before processing.

Phase 7 Extension — Live Preview + GitHub Push

  1. Preview tab composes in-memory files and injects CSS/JS into HTML srcdoc.
  2. GitHub modal collects repo, PAT, branch, message and posts to github_push.php.
  3. Backend creates tree → commit → ref update and returns commit URL.

Typical Workflow: Prompt to Deploy (Landing Page Example)

Scenario

User prompt: "Build a modern SaaS landing page with hero, pricing cards, FAQ, and contact form."

  1. Prompt Input: User submits request in chat box.
  2. Reasoning Phase: Right pane shows model planning and generation status in real time.
  3. Code Generation: Assistant streams one or multiple files (e.g. index.html, style.css, script.js).
  4. Code Interaction: User reviews tabs, copies snippets, or downloads individual files.
  5. Live Preview: User opens Preview tab to validate layout, interactions, and responsive feel.
  6. Iteration: User asks follow-up changes ("make it minimal", "add testimonials", "change palette").
  7. Deploy: User presses F10 or clicks 🚀 Deploy.
  8. Live URL: Backend returns /deploy/{user}/{session} link for immediate browser access.
  9. Optional Publish: User pushes same files to GitHub from the generated code action.

Result: fast loop from idea → generated code → preview → live deployment in one workspace.
